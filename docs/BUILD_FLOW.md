# PaperTrans 构建流程

> 当前状态：M0-M3、M4.1-M4.3、M5.1、M5-C、M6.1-M6.4、M7.1-M7.5 已完成并通过用户验收。Windows `0.1.1` 冻结修正版、自包含 Python sidecar 与 NSIS 安装包已完成。

## 1. 产品目标

PaperTrans 的长期目标是将外语学术 PDF 翻译为中文，并在保证内容完整、文字可读的前提下，尽量保持原页面尺寸、页数、图片、表格、公式和视觉层级。

项目不把“像素级绝对不变”作为承诺，因为语言变化必然导致文本长度和换行变化。工程目标是通过文档级约束求解，使总体版式失真最小。

## 2. V0范围

V0只处理文本型英文论文：

- 支持常见单栏和双栏页面。
- 原生提取PDF文字、坐标、字体和图片区域。
- 建立可版本化的Document IR。
- 输出布局可视化，允许人工检查阅读顺序和区域分类。
- 公式、表格、图注和参考文献在V0中只允许标记或原样保留。
- 不使用OCR，不下载任何模型。
- 不构建桌面UI。

V0完成标准不是“能够翻译任意PDF”，而是对基准论文建立可观察、可回归的解析基础。

## 3. 总体管线

```text
PDF输入
  → 原生PDF对象解析
  → 页面视觉渲染
  → Document IR
  → 版面区域分类
  → 阅读顺序和文本流恢复
  → 段落分割与保护标记
  → 翻译提供方
  → 译文长度候选
  → 全局版式求解
  → PDF内容重建
  → 自动质量检查
  → 中文PDF
```

扫描件支持加入后，OCR结果会与原生PDF结果在Document IR之前融合，而不是替换整条管线。

## 4. 分阶段构建

### M0：项目初始化与PDF检查器

交付物：

- Python包、命令行入口、测试和代码检查配置。
- `Document`、`Page`、`Region`、`BoundingBox`、`TextStyle`。
- `papertrans inspect` 命令。
- `document.json`、页面预览、布局标注图和检查报告。
- 确定性的Mock翻译提供方。

质量门槛：

- 新环境可以通过一组命令安装并运行。
- 测试生成的PDF可以稳定产出检查文件。
- 所有区域拥有稳定ID、坐标和明确的可翻译标志。
- 当前启发式能力和限制必须写入报告，禁止伪装为生产级识别。

### M1：论文结构与阅读顺序

交付物：

- 页面列检测。
- 单栏、双栏和跨栏区域关系。
- 行合并、英文断词修复和段落恢复。
- 标题、摘要、正文、页眉页脚、图注、表注和参考文献分类。
- 可视化阅读顺序箭头和人工修订用JSON。
- 段落级 `text-flows.json`，保留每段对应的页面和原始区域ID。
- 物理换行清理，以及带置信度的断词、跨栏和跨页续接决策。

质量门槛：

- 基准集正文阅读顺序达到预先确定的准确率。
- 不允许将左右栏同一高度的行错误拼成一个句子。
- 页眉、页脚和页码不得进入正文翻译。
- 文本完整率、区域分类准确率和阅读顺序必须分别记录。

### M2：零翻译回环

交付物：

- 解析原PDF后，使用原文重新排版并生成新PDF。
- 中文字体注册、测量、回退和嵌入能力。
- PDF输出中的图片、基本矢量对象和链接保留。
- 页面视觉对比和内容完整性检查。
- `papertrans roundtrip` 命令和 `roundtrip-report.json`。
- span级基线坐标、字号、颜色和字体类别映射。
- 重绘后恢复源PDF链接注释。

质量门槛：

- 使用原文回环时页面数不变。
- 文字无明显重叠、截断和遗漏。
- 图片、公式保护区域和链接数量差异可检测。
- 输出文本可选择、复制和搜索。

如果零翻译回环没有通过，不得进入真实翻译阶段。

当前基线实现采用白色区域填充清除原文字形，仅面向白底学术论文。彩色背景、纹理背景和与文字重叠的矢量元素需要后续升级为PDF内容流级文字抑制。

### M3：伪翻译与版式压力测试

交付物：

- Mock翻译器生成不同长度的CJK文本。
- 中文断行和标点禁则。
- 同一文本流内的跨区域流动。
- 基础排版规则：字号、行距、字间距和紧凑译文选择。
- 溢出、重叠、低字号和位置变化报告。

质量门槛：

- 正常长度和加长场景均有确定的回归结果。
- 同类正文不得各自任意缩放字号。
- 无法安全放置的内容必须失败或告警，不得静默裁切。

当前实现基线（2026-07-30）：

- `papertrans translate <pdf> --provider mock --length-factor <factor>` 生成可检查的完整中间产物。
- 本地 CJK 字体解析、中文标点禁则、跨区域 TextFlow、普通/紧凑候选和最小 72% 字号回退已接通。
- 四篇标准长度论文均为 PASS：零溢出、零新增低于 6pt 的文字、页数和页面尺寸不变、链接保留。
- Fast R-CNN 的 1.3 倍加长场景为 PASS；最小字号比例为 0.7202，未发生静默裁切。
- YOLO 公式碎片已通过公式邻域保护规则修复，并加入最小回归测试。
- 页面级占用检查会跳过与既有译文或受保护区域碰撞的行槽，再尝试紧凑候选和字号回退。
- 译文擦除区域会为公式、图表等受保护区域创建镂空，避免清除与正文框相交的原始内容。
- `translated_line_overlap_count` 和 `protected_region_overlap_count` 必须同时为零，否则任务进入 REVIEW。
- 当前仍采用白色区域填充，只覆盖白底学术论文；该限制写入每次质量报告。

### M4：真实翻译

规划提供方：

- DeepSeek、Kimi 及自定义 OpenAI-compatible API（M4.3 已完成）。
- Google翻译适配器（后续独立里程碑，不属于 M4.3）。
- Mock提供方继续作为测试依赖。

翻译流程必须支持：

- 按段落翻译，而不是按PDF行翻译。
- 公式、引用、URL、DOI、变量和单位占位保护。
- 章节上下文和术语表（已在 `M5-C：翻译语境增强` 中实现受限版本）。
- 普通译文和紧凑译文候选。
- 请求缓存、重试、限速、断点恢复和费用记录。
- 密钥只从环境变量或本地未跟踪配置读取。

质量门槛：

- 保护标记全部恢复且无重复。
- API失败不会破坏已有任务产物。
- 相同输入、配置和缓存应产生可复现输出。
- 未配置付费API时仍可使用Mock完成全部本地测试。

当前 M4.1 基线（2026-07-30）：

- 引用、URL、DOI、LaTeX片段、显式变量及常见数值单位会替换为 `⟦PT0001⟧` 形式的段落内稳定占位符。
- `protected-segments.json` 在调用提供方前以 `prepared` 状态落盘，成功恢复后更新为 `validated`。
- 普通译文和紧凑译文分别检查缺失、重复和未知占位符；任一检查失败都会中止排版。
- 四篇基准论文共验证数百次占位符恢复，缺失、重复和未知计数均为零，PDF质量门全部 PASS。
- 当前仅 Mock 提供方接入保护层；提供方可靠性能力由下述 M4.2 基线统一提供。

当前 M4.2 基线（2026-07-30）：

- `ReliableTranslationProvider` 为任意提供方增加逐段原子磁盘缓存、指数退避重试和请求速率限制。
- 缓存键包含提供方配置指纹、语言、保护后文本、上下文和占位符；不包含API密钥。
- 每个成功段落立即写入缓存，后续段落失败不会破坏已完成结果；下次运行从缓存继续。
- `provider-run.json` 在请求前以 `prepared` 状态落盘，成功或失败后记录统计及不含论文正文的错误摘要。
- Fast R-CNN 双运行验证中，第二次139段全部命中缓存，提供方调用为零；两次译文、布局和PDF质量指标一致。
- M4.3 在此保护与可靠性层之上接入命名提供方和通用兼容模式。

当前 M4.3 基线（2026-07-31）：

- `translate --provider deepseek|kimi|compatible` 由用户显式选择；`mock` 保持默认且不发出外部请求，不存在自动提供方故障切换。
- DeepSeek 默认使用 `deepseek-v4-flash`，Kimi 默认使用 `kimi-k2.6`，两者以非 thinking 模式请求；`compatible` 必须显式提供绝对 HTTP(S) base URL 和模型，并标记为 best-effort。
- 共享 Chat Completions 客户端一次 JSON 响应同时接收完整译文和紧凑译文；占位符预检查失败可重试，最终恢复失败会阻止 PDF 渲染。
- API 密钥只从环境变量读取。缓存身份、任务 JSON、失败摘要和测试产物均不得持久化密钥；外部服务只接收经过占位符保护的段落文本及上下文，不上传整份 PDF。
- DeepSeek 和 Kimi 的新调用会归一化记录输入、缓存输入和输出令牌，并根据 `2026-07-31` 的公开价格快照估算费用；缓存命中不产生本地估算费用。
- 永久 HTTP 错误不重试；网络超时、408、429 和 5xx 可按策略重试。任何段落失败都保留此前已经原子写入的缓存。
- DeepSeek 与 Kimi 形态的 `MockTransport` 全 PDF 测试均验证了引用、URL、单位和占位符恢复、密钥不落盘、缓存续跑、用量/费用、零译文重叠和零保护区碰撞。
- 真实论文 `1411.4038v2.pdf` 的离线 `--provider mock` 质量门为 PASS，七项翻译产物齐全；不需要外部密钥、网络或模型下载。

### M5：版式安全验证与渐进式求解

先用确定性的有限局部修复与独立约束复验降低：

```text
文本溢出
+ 元素重叠
+ 字号变化
+ 行距和字间距变化
+ 原位置偏移
+ 同类样式不一致
+ 页面数量变化
```

硬约束包括：

- 文字不得遮挡公式、表格或图片。
- 字号不得小于产品设定的可读阈值。
- 标题、正文、图注和脚注的语义关系不得颠倒。
- 页面对象不得越界。
- 内容不得静默丢失。

M5.1 不预先实现 Beam Search、冲突图或专门优化库。只有真实失败样本反复证明有限局部
修复不足时，才扩展为页面级搜索；无安全解时进入 REVIEW，且不得创建或覆盖输出 PDF。

当前 M5.1 基线（2026-07-31）：

- 复用普通/紧凑译文、0.5pt 字号阶梯、72% 比例和 6pt 下限进行有限局部修复。
- 独立验证器从 Document 几何与最终 LinePlacement 复查流完整性、页边界、字号和碰撞。
- 不安全布局不调用渲染器；临时 PDF 只有通过全部 PDF 质量门后才原子替换正式输出。
- 四篇真实论文普通长度场景全部 PASS，溢出、译文重叠、保护区域重叠和新增低于 6pt 均为零。
- Fast R-CNN 1.3 倍加长场景继续 PASS，最小字号比例为 0.7202。

#### M5-C：翻译语境增强

在 M5.1 版式安全基线之上，M5-C 增加受限的章节级上下文、术语表和相邻段落上下文。
该能力不绕过既有的逐段保护、缓存、隐私与质量门；跨段批处理继续延期。

当前 M5-C 基线（2026-07-31）：

- 每段携带最近章节标题（最多 200 字符）和前后相邻可翻译流（各最多 600 字符）。
- 提示词明确只翻译当前受保护段落，邻段仅用于术语和语义连贯，不得复制进译文。
- `--glossary` 接受最多 500 项的 UTF-8 JSON 对象，并只向当前段发送命中的术语。
- 提示词版本、章节标题、邻段和相关术语均进入现有哈希缓存身份；不在缓存元数据中保存正文。
- `translation-report.json` 只记录上下文覆盖与裁剪计数，不记录邻段或完整术语内容。
- 真实论文离线 Mock 验收覆盖 117 个文本流，PDF 质量门为 PASS，零溢出和零碰撞。
- 全文单请求、向量检索、自动术语挖掘和跨段提供方批处理继续延期。

### M6：OCR与扫描件

只有M0到M5的文本型PDF链路稳定后才引入OCR。

候选方向：

- PaddleOCR用于文字识别、版面区域和表格分析。
- OCR仅作用于没有可靠文字层的页面或区域。
- 原生文字、OCR文字和页面视觉结果必须保存各自置信度和来源。
- 低置信度页面进入人工检查，而不是直接导出。

模型下载规则见第8节。

当前 M6.1 基线（2026-07-31）：

- `ocr-plan.json` 使用 `m6_ocr_plan_v1`，记录固定策略、汇总计数和逐页诊断，不保存页面图像或论文正文。
- 页面动作包括 `keep_native`、`run_ocr`、`review` 和 `skip_blank`；每项决策都带置信度和原因码。
- 决策依据为原生非空白字符数、可疑字符比例、栅格图片联合覆盖率和原生矢量对象数量。
- 原生文字来源写入 Region 与 TextFlow 元数据；OCR 结果接入后必须使用独立来源和置信度。
- `run_ocr` 与 `review` 会在翻译 provider 调用前失败关闭，并保留已有 `output.pdf`。
- layout overlay 右上角直接显示逐页 OCR 动作，便于人工核验。
- 四篇真实文本型论文全部保持 `keep_native`；五页合成混合样本依次得到原生、OCR、复核、空白和复核动作。
- M6.1 不运行 OCR，不安装 OCR 运行时，也不下载任何模型。

当前 M6.2 基线（2026-07-31）：

- PaddleOCR 3.7.0 与 PaddlePaddle 3.3.1 作为可选 `ocr` 依赖；默认路径仍不导入或初始化 OCR 后端。
- `--ocr-backend paddleocr --ocr-model-dir <目录>` 显式启用本地识别，默认 CPU、200 DPI，且只渲染初始动作是 `run_ocr` 的页面。
- 本地 PP-OCRv6 medium 检测与识别模型由用户预先解压；路径解析兼容识别模型额外嵌套一层，程序不下载权重。
- Windows CPU 基线关闭 MKL-DNN/oneDNN：相同模型在 Paddle 3.3.1 的 oneDNN PIR 指令转换中失败，关闭后真实推理成功。
- OCR 行按像素多边形映射回 PDF point 坐标，以 `content_source=paddleocr`、引擎置信度和原始多边形写入 Region，再重新恢复结构与 TextFlow。
- `ocr-plan.json` 升级为 `m6_ocr_plan_v2`；达到 40 个非空白字符且平均置信度至少 0.80 的页面进入 `use_ocr`，低质量结果保持 `review`。
- `ocr-run.json` 只记录后端、设备、候选页数及接受/拒绝行数，不保存正文、密钥或模型绝对路径。
- 扫描底图标记为 `ocr_background` 并保留视觉内容，但不再作为翻译布局的保护碰撞框；OCR 遮罩轻微外扩以清除栅格字形边缘。
- 合成扫描页真实识别得到 21 行且零拒绝，OCR 到 mock 翻译、布局和 PDF 渲染闭环质量门为 PASS；原生页保持零 OCR 调用。

当前 M6.3 基线（2026-07-31）：

- PaddleOCR 物理行按同栏、相近行高、连续垂直间距、水平重叠和段首缩进恢复为段落级 TextFlow；每条连接以 `ocr_same_paragraph` 和置信度留痕。
- 单栏页面使用的栏编号与双栏编号均进入连续性分析；跨栏不会被 OCR 专用规则误合并。
- 双栏检测为 PaddleOCR 行使用 6pt 高度下限，原生段落块继续保持 12pt 证据门槛。
- `inspect --ocr-reference <pdf>` 输出 `m6_ocr_quality_v1`，包含逐页及汇总 CER、词序相似度、字符覆盖率和明确质量门，不保存论文正文。
- ResNet 论文第 2 页以 200 DPI 栅格化为无文字层扫描代理：CER 0.026003、词序相似度 0.96702、覆盖率 1.001282，质量门 PASS。
- 同页 107 个识别区域恢复为 10 个 TextFlow，产生 85 条 OCR 行连接和 8 个合并段落流；mock 翻译 PDF 的溢出、低字号、译文碰撞和保护区碰撞均为零。
- 当前基线是带精确文字真值的真实论文栅格化代理，不冒充真实物理扫描件；真实纸张噪声、倾斜、阴影和压缩损伤仍需用户样本验证。

当前 M6.4 基线（2026-07-31）：

- 只有用户显式启用 OCR 时才会检查混合页图片；默认原生提取路径和外部 provider 调用边界不变。
- 较大图片按 PDF 裁剪框单独渲染，OCR 像素坐标带裁剪偏移映射回页面坐标，不对整张混合页重复识别。
- OCR 行与可靠原生文字重叠面积达到阈值时丢弃；局部结果至少包含 3 行、80 个非空白字符且平均置信度至少 0.80 才作为正文融合。
- 通过门槛的图片标记为 `ocr_background`，页面动作进入 `use_mixed`；稀疏图表标签被忽略，原图片继续受布局保护。
- `ocr-run.json` 升级为 `m6_ocr_run_v2`，仅记录候选、接受、忽略区域和重复行计数，不记录论文正文。
- 实际 PP-OCRv6 混合论文页识别 7 行，平均置信度 0.9218；mock 翻译 PDF 无溢出、无新增 6pt 以下文字、无译文或保护区碰撞，质量门 PASS。
- 按用户选择，本阶段不把低质量手机拍摄、严重倾斜、阴影或噪声作为阻塞测试；这类输入仍属于未验证范围。

### M7：编辑器与产品化

- 第四质量门已通过用户验收：仓库任务删除必须显式确认且运行中任务不可删除。PDF 删除只移除历史索引，原始论文和生成译文均保留；文本删除原子移除索引及 `.papertrans/library/<task-id>/` 内的应用托管副本。设置页分别统计并清理翻译缓存和无引用的临时上传副本；所有删除目标先被约束在应用托管根目录内，符号链接和 Windows reparse point 不会被递归跟随。缓存清理在翻译运行期间被阻止，原始 PDF、输出目录、API Key、任务正文和诊断均不进入清理范围。
- 桌面生命周期补充已实现并纳入第四质量门验收：默认关闭主窗口时由 Tauri 拦截关闭请求并隐藏到系统托盘，不卸载 React/PDF.js 工作区，也不结束 FastAPI 子进程。单击托盘图标或“显示 PaperTrans”恢复并聚焦窗口；托盘“退出 PaperTrans”或开启设置项“关闭主窗口时退出应用”后关闭，才触发真实应用退出和既有后端清理。关闭偏好不含敏感信息，可保存于当前 WebView 用户存储。
- 仓库和设置仍按需挂载，避免把非阅读页面永久保留在内存；更换任务或主动移除 PDF 时继续走既有资源清理路径。

## 5. 工作产物约定

每个任务使用独立目录：

```text
.papertrans/jobs/<job-id>/
├── source.pdf
├── job.json
├── document.json
├── ocr-plan.json
├── protected-segments.json
├── translations.json
├── layout.json
├── qa-report.json
├── output.pdf
├── pages/
└── overlays/
```

中间产物必须可检查、可缓存、可从失败阶段继续。禁止只把状态保存在进程内存中。

## 6. 基准集与质量指标

在实现翻译前建立小型论文基准集，逐步覆盖：

- 单栏与双栏。
- 跨栏标题和图片。
- 大量公式。
- 表格、脚注和参考文献。
- 不同出版社模板。
- 字体编码异常。
- 扫描页和混合页。

核心指标：

- 内容完整率。
- 阅读顺序准确率。
- 区域分类准确率。
- OCR字符错误率。
- 文本溢出率。
- 元素重叠率。
- 最小字号和字号一致性。
- 页面数量保持率。
- 图片、公式、链接和脚注保持率。
- 视觉差异和人工可读性评分。

所有重要修复都应加入一个最小回归样本。

## 8. 模型和大型文件下载规则

- M0到M5不得要求任何OCR模型。
- 代码不得在导入模块时隐式下载模型。
- 需要模型时，先向用户提供：模型名称、官方来源页面、官方直链、文件大小、校验值（如官方提供）和建议本地目录。
- 默认模型目录为仓库根目录下的 `models/`，该目录不提交Git。
- 用户下载完成并确认本地路径后，代码只读取本地文件。
- 如需提供自动下载器，必须是用户显式执行的独立命令，并支持断点续传和校验。
- 不采用来源不明的模型镜像或网盘文件。

## 9. 安全与隐私

- PDF可能包含未公开论文和敏感内容，本地解析优先。
- 外部翻译前必须明确使用了哪个提供方。
- API密钥不得写入源码、日志、任务JSON或测试夹具。
- 日志默认不打印完整论文段落。
- 任何遥测都必须默认关闭并经用户明确启用。
